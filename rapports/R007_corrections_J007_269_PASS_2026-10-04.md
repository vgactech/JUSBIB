## Correction 2 — AM10 : compute_snapshot() — version_id au niveau racine

### Fichier : `juslib/src/juslib/db.py`

**AVANT (lignes 864–872) :**
```python
            results.append({
                "provision": dict(prov),
                "version": version,
                "is_in_force": bool(is_in_force),
                "version_status": status_info["status"],
                "snapshot_date": on_date,
            })
```

**APRÈS (lignes 864–874) :**
```python
            entry: dict[str, Any] = {
                "provision": dict(prov),
                "version": version,
                "is_in_force": bool(is_in_force),
                "version_status": status_info["status"],
                "snapshot_date": on_date,
            }
            if version:
                entry["version_id"] = version["version_id"]
            results.append(entry)
```

**Explication :** Le test `AM10` cherchait `s.get("version_id")` directement dans chaque entrée du snapshot. La méthode `compute_snapshot()` retournait la version imbriquée sous la clé `"version"` mais ne remontait pas `version_id` au niveau racine. La correction ajoute ce champ au niveau racine conditionnellement (si `version is not None`), ce qui permet au test de localiser `ver_id_2` dans le snapshot au 2026-01-01.
